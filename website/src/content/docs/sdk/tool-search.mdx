Tool search lets the model find the functions it needs from a large set of tools. Their definitions can be loaded as they are needed, which reduces the amount of tool information included in the prompt.

Tool search is enabled by adding a `ToolSearchTool` to the request. Function tools with `defer_loading` set to `true` are available through search, while the other tools are available to the model from the start. All definitions are still included in the request's `tools` list so the provider can find them. Availability is listed in [Supported providers](../providers).

```ts
const response = await model.generate({
  messages: [{ role: "user", content: [{ type: "text", text: "..." }] }],
  tools: [
    { type: "tool_search" },
    { type: "function", name: "get_weather", description: "...", parameters },
    {
      type: "function",
      name: "lookup_holiday",
      description: "...",
      parameters,
      defer_loading: true,
    },
  ],
});
```

## Search calls and results

When the model searches for tools, its response includes a `ToolCallPart` describing the search and a `ToolResultPart` containing the results. These are the same part types used for [web search](../web-search).

The `tool_names` field of `ToolSearchToolResult` identifies the functions found by the search. Including both the search call and its result in the assistant message history allows the model to use that information in later requests. The function definitions must also remain in the `tools` list on each request.

The provider performs the search and returns its results. If the model then calls one of the functions it found, your application executes it and returns the result as described in [Function calling](../function-calling).

When streaming, search calls and results arrive as partial responses. The accumulator combines them into the same parts returned by `generate`.
